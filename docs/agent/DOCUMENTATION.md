# Agent Documentation System

> Authority：文档分层、生命周期、拆分与跨 Agent 适配规则
>
> Read when：新增、拆分、合并、移动或归档文档；需要为新的 coding agent 增加入口
>
> Update when：文档系统本身的结构或维护规则变化

## 1. 设计目标

文档库的目标不是记录所有信息，而是让一个没有历史对话的新 Agent 用最少上下文找到完成当前任务所需的权威知识。

衡量标准：

- **入口稳定**：所有 Agent 从根目录 `AGENTS.md` 开始。
- **按需加载**：一个常见任务通常只需索引加一至两个主题来源。
- **单一权威**：同一事实不在多份文档中分别维护。
- **状态可验证**：会变化的事实由工具现场确认，不靠静态文档猜测。
- **更新有归属**：行为变化时能立即知道应更新哪份文档。

## 2. 文档分层

1. **入口层**：`AGENTS.md`。只保存启动协议、事实路由和全局协作规则。
2. **权威主题层**：产品、领域、未来架构与开发文档。每份文件只负责一个稳定知识范围。
3. **决策层**：ADR。保存重要技术选择的背景、理由和后果，不重复当前规范。
4. **状态层**：`PROJECT_STATE.md`。帮助跨 session 续接，但任何动态内容都必须现场验证。
5. **实时证据层**：代码、测试、Git、CI、GitHub 与实际运行结果，不转抄成长期静态事实。

不要再创建第二份全局索引。若主题文档将来增多，仍由 `AGENTS.md` 按“任务”路由，而不是让 Agent 按目录逐层浏览。

## 3. 每份耐久文档的头部

使用简短的 Markdown 引用块，不使用容易腐化的复杂 front matter：

```markdown
> Authority：这份文件唯一负责什么
>
> Read when：什么任务需要加载
>
> Update when：什么变化必须同步更新
```

作者和修改时间由 Git 提供，不在每页手工维护。只有带时间语义的实验记录才写明观察日期、环境和基准 commit。

## 4. 新建与拆分规则

只有同时满足以下条件，才新增主题文档：

1. 它拥有可清楚命名的独立职责；
2. 有一类任务会单独读取它；
3. 内容有自己的更新节奏；
4. 从现有文件拆出后不会复制事实；
5. `AGENTS.md` 能为它增加明确的任务路由。

在对应的真实职责出现前，不预建空的 architecture、development、testing 或 release 文档。第一批真实 module 出现后，如果 PRD 某组章节会被反复独立读取，再把它迁为相应的 spec 或架构文档，并在原位置改成链接；已有主题文档也只能描述现场存在的代码、命令与流程。

以下事件会直接触发扩展评估：

- 首次形成真实、跨 module 使用的 interface 或 seam 时，创建 `docs/architecture/OVERVIEW.md`；
- 首次形成稳定的环境准备、构建或测试命令时，创建 `docs/development/SETUP.md`；
- 首次形成可重复的发布流程时，创建 `docs/development/RELEASE.md`。

这些路径只表示未来的职责位置；触发前不得创建空文件。

## 5. 单一权威与冲突处理

- 摘要只能缩短导航成本，不能重新定义事实。
- 需要引用其他主题时，链接到权威文件及章节，不复制规则列表。
- README 只解释项目是什么、当前能否安装和如何开始，不承担完整产品规范。
- ADR 解释“为什么选择”，当前主题文档说明“现在应怎样”。
- 代码与规范不一致时，在任务中明确冲突，并决定修代码、修文档或请求产品确认。
- 已接受 ADR 不改写历史结论；通过新的 ADR 取代，并更新当前主题文档。

## 6. 动态状态与跨 session 交接

分支、未提交改动、测试结果、依赖版本、发布状态和外部网络行为均属于动态事实。Agent 必须运行相应命令重新观察。

`PROJECT_STATE.md` 只保留当前阶段、已完成能力、下一里程碑和已知阻塞，不保存每日流水账。阶段改变时替换旧内容，Git 历史负责追溯。

如果一项工作必须在未完成时跨 session 交接，才创建 `docs/agent/handoffs/<task>.md`，至少包含：

- 目标与范围；
- 基准 commit 和已修改路径；
- 已验证证据；
- 剩余工作与风险；
- 接手后首先要重新运行的命令。

任务完成后删除 handoff；有长期价值的知识迁入权威主题文档或 ADR。

## 7. 不同 coding agent 的适配

`AGENTS.md` 是唯一规范入口。如果某个工具只自动读取专用文件，例如 `CLAUDE.md`，可以在首次真实使用该工具时增加一个极薄 adapter，内容只要求读取并遵循 `AGENTS.md`。

adapter 不得复制任务路由、产品事实或协作规则。尚未使用的工具不预建 adapter。

嵌套 `AGENTS.md` 也只在某个子树拥有不同的构建、验证、安全或生成规则时创建。普通 module 知识属于代码、测试或架构文档，不能靠增加入口文件分散维护。

## 8. 文档变更检查

- 新事实是否已有权威归属？
- 是否删除了其他位置的重复表述？
- `AGENTS.md` 的任务路由和文档地图是否仍准确？
- 所有相对链接是否存在？
- 动态结论是否附有现场验证方法？
- 行为变化是否同时更新测试或验收标准？
